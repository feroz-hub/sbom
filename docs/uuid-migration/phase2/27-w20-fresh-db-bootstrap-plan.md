## Final six-table UUID schema

Common final contract: non-PK native `uuid public_id`, persisted **NOT NULL**, database INSERT default `pg_catalog.gen_random_uuid()`, explicit-NULL INSERT allocation, validated canonical-v4/variant CHECK, one full per-table unique B-tree backing a nondeferrable UNIQUE constraint, and current immutable identity guard. Preserve original integer IDs/FKs/sequences, tenant columns, lifecycle/timestamps and business constraints. No UUID FK conversion, UUIDv7, deterministic ID conversion or random-on-read identity.

| --- | --- | --- |
| tenants / Tenant | `uq_tenants_public_id` | Resolve root UUID through eligible membership/platform policy; retain integer root and incoming tenant FKs. |
| projects / Projects | `uq_projects_public_id` | UUID + authorized integer tenant, preserve project/product/source associations. |
| products / Product | `uq_products_public_id` | UUID + tenant + required project; preserve integer current_sbom and composite logical relationships. |

| sbom_source / SBOMSource | `uq_sbom_source_public_id` | UUID + tenant + logical/product/project validation; preserve integer version/self/conversion lineage. |
| sbom_component / SBOMComponent | `uq_sbom_component_public_id` | UUID + tenant + parent source; integer occurrence and duplicate/self-FK retained. |

Finalization order on the fresh quiescent installation: apply080–085 before any customer/core fixture insertion; assert six tables have no legacy NULLs/duplicates; build unique indexes/constraints, validate existing v4 CHECKs, enforce NOT NULL, verify catalog semantics and marker, then permit seeds/admin/application writes. Reference migrations048–079 do not substitute for this finalization. Core tables unexpectedly populated before expand/finalization are a failed freshness/order gate: stop, do not invoke backfill automatically. Reference rows in noncore catalogs are expected and separately verified.

No concurrent-index machinery is necessary merely because the old design used it: with writers barred on a new database, ordinary transactional unique creation can be simpler. Select one explicit ordinary-index/constraint definition per table, with no duplicate auto-created indexes; concurrent creation remains a separate choice for live upgrades, not an implied requirement here. Actual final migration identifiers are **not reserved** by this plan; resolve then-current graph and publish reviewed new revisions after085. Never rewrite080–085 to make their transitional contract appear final.

CHECK NOT VALID still enforces new rows today; validate it for the final catalog. NOT NULL is necessary even with the allocator: an additional INSERT trigger or privileged bypass can otherwise leave NULL. Keep the AFTER UPDATE `WHEN OLD.public_id IS DISTINCT FROM NEW.public_id` guard; it observes final NEW after BEFORE triggers and rejects changing/removing an assigned UUID, while same-value/unrelated changes remain valid. Transitional NULL→valid assignment remains in source but is unreachable for ordinary final-schema rows. Do not disable constraints to manufacture it in the final deployment.

Concurrency acceptance must prove atomic default allocation, unique-index races/23505 and immutable-update rejection/rollback with real PG connections. Duplicate explicit valid UUIDs must fail in the final schema; random generation is not a mathematical uniqueness guarantee. Deletes/soft deletes retain existing policy; live-row uniqueness plus immutability do not prove all-history non-reuse after hard deletion. Tombstone/non-reuse policy remains a contract decision. Runtime roles must lack DDL/trigger-disable/replication-bypass privileges; owner/superuser control is an explicit trust boundary, not defeated by ordinary triggers.

All six current [model classes](/Users/ferozebasha/sbom/app/models.py:32) lack public_id. Future mapping: PostgreSQL UUID(as_uuid=True), nullable=False and matching server_default plus named schema constraints, with server-returned values after flush/INSERT RETURNING. Do not replace the integer id column or serialize Python UUIDs incorrectly. Review bulk/ORM/raw/COPY/upsert/clone/event paths; no Python onupdate/default or serialization-time generator may reassign identities. SQLite metadata tests are not PostgreSQL trigger/constraint acceptance.
