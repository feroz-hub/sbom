## Classification and evidence

Classification applies to the **specific reference and hop**, not globally to the model: **Internal-only** means an in-process, DB, broker, cache-key, lock or operational-log reference with no external consumer identified at that hop. **Externally exposed** means transported to an authorized API/UI client, SSE subscriber, email recipient, downloadable artifact or configured upstream service. Authenticated/admin-only is still external exposure. Internal Redis/Celery transport is infrastructure within the application trust boundary; its payload can subsequently become externally exposed in a separately listed projection. Neither classification asserts that an ID is secret or an access-control weakness.

**Verified** means inspected source establishes the producer/consumer or declared contract. **Nested IDs suspected** is used for open JSON/snippet/user content whose arbitrary runtime contents were not inspected. A registered task/adapter is not proof of deployment execution. Source links refer to the current working tree, including existing frontend edits; no runtime/deployment claims are made.

Coverage includes all 15 statically registered Celery tasks in app Python source, all 17 discovered apply_async/delay/add_task/create_task dispatch sites, broker serialization, Beat definitions, Redis progress/cancellation/config/locks, DB-backed caches, report and security-mail outboxes, VEX/remediation/recommendations, exports and HTTP/provider adapters. The declaration sweep records 81 mapped JSON/JSON-text candidate columns; those are potential carriers, not 81 proven surrogate-ID fields.

## Main findings affecting UUID migration

- Integer assumptions occur after the HTTP boundary: exact-int actor authorization, hierarchical scheduler int casts, the declared AI finding-list deserializer, credential/model casts, compare hashing, metric MAX(id)/int conversion, historical VEX JSON integer joins and report ranking arithmetic. Changing only SQL PK/FK columns would leave these flows incompatible.
- JSON keys and values both carry identities: completed report outcomes use stringified SBOM IDs as object keys; arrays still contain typed record IDs. Old messages, history snapshots, retained artifacts, email URLs and cache entries preserve the previous representation.
- Existing UUIDs are mixed with integer resources: AI batch/session/repair job IDs and private artifact filenames are already strings; run, tenant, finding and imported SBOM references inside the same structures are still numeric.
- AuditLog has two identity slots: string entity_id and legacy numeric target_id; int conversion failure can silently remove the latter, while history queries still depend on it.
- Security mail exposes the action-token row ID in Message-ID and binds it into outbox encryption AAD. This dependency is separate from the opaque activation/reset token in the URL fragment.
- No webhook publisher, subscription model, receiver route or callback URL field was found by case-insensitive source search for webhook/callback_url/notification_url in app, KEV and scripts. This is a repository finding, not proof no deployment-side integration exists. Outbound provider HTTP calls and SMTP delivery are verified integration surfaces below.
