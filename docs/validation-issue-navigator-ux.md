# Validation Issues navigator refinement

Scope: only the issue panel on `/repair/:sessionId`. Existing page layout, editor, revalidation, APIs and business rules were retained.

1. **Files changed:** `frontend/src/components/sboms/repair/RepairIssueNavigator.tsx`, its new `RepairIssueNavigator.test.tsx`, `frontend/src/lib/repairIssuePresentation.ts`, its existing test file, `frontend/src/components/sboms/ValidationRepairWorkspace.tsx` (panel prop wiring only), its existing test file, and this report.
2. **Panel component:** refined `RepairIssueNavigator`; no new page redesign or editor implementation.
3. **Status summary:** title followed by compact Passed/Failed/Awaiting validation and grammatical counts. Removed the large success card from the scrollable issue list. Informational findings have their own count when present.
4. **Issue hierarchy:** small severity marker and ordinal, human-readable title, secondary short technical code, labeled monospace location, short description, location action. Raw output and repair guidance are separate native disclosures. Selected rows use subtle blue and a 3px blue left edge instead of a heavy full outline; unselected rows are neutral.
5. **Title mapping:** added deterministic Orphan component mapping for I075, confirmed against `app/validation/stages/integrity.py`. Original code and message remain untouched. Short secondary display is SBOM_VAL_I075. Unknown codes use a readable code suffix rather than the generic Validation issue title. Search includes the full original code.
6. **Go to location:** relabeled the existing action; existing exact JSON offset/reported-line/server-search navigation and honest Copy path fallback remain unchanged. No line numbers were invented.
7. **Selection/editor synchronization:** existing selection callbacks still drive editor selection and highlighting. Exactly one issue receives selected styling and aria-current; selected position appears in Previous/Next controls and card ordinal.
8. **Filters:** replaced select dropdown with keyboard-accessible All, Errors and Warnings buttons; Info appears only when actual info entries exist. Existing automatic/manual classifications remain available as chips only when nonzero. All filters update the same independently scrolling list.
9. **Passed with warnings/info:** compact Passed summary above remaining findings and No blocking errors below. Orphan component remains INFO because the actual validator explicitly classifies I075 as informational; it is not relabeled WARNING based on an example screenshot.
10. **Failed state:** Failed summary, actual error count, severity-filtered list, blocking-error footer and existing import-disabled explanation.
11. **Accessibility:** severity text, named filter group, aria-pressed filter buttons, aria-current issue selection, readable Previous/Next controls with names/tooltips and live position, existing Alt+Up/Down shortcuts, keyboard-selectable cards, accessible disclosures, and existing editor focus behavior. Panel retains current responsive page tabs and independently scrolling issue list.
12. **Tests:** 65 tests passed across five suites: navigator, workspace, issue presentation/source mapping, existing automatic repair and existing quality panel. New checks cover informational severity preservation, passed-with-warnings filters/search, parent import gating, failed selection, and clean report access. TypeScript and targeted ESLint passed. No live import was performed.
13. **Build:** production Next.js/Turbopack build passed in an isolated copy of the frontend, without disturbing the development build output.

Readiness is passed into the panel from the workspace's existing `importReady` and `importHint`; the panel does not independently decide eligibility. Clean sessions offer View validation report using the existing report download. Validation codes, severity semantics, repair/auto-fix/manual rules, editor content, quality calculations, revalidation behavior, security and import gates were not modified.
