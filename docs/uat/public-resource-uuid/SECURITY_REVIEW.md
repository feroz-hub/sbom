# Security review

UUIDs identify resources; they do not grant authority. Existing route authentication, permissions and tenant dependencies run before new-resource resolution. Membership and Run lookups include tenant_id. Platform Grant lookup requires a platform administrator, no active tenant, and the platform route. Unauthorized operations retain 403; authorized missing/foreign selectors use concealed 404; malformed/integer selectors use 422; existing stale/duplicate conflicts retain 409.

The serializer batches distinct references in chunks of 500 per entity and request. It never infers an entity from arbitrary JSON `id`. Explicit response models, route families and named fields control conversion. Audit event IDs, finding IDs, role-assignment/event IDs, counts and source-native document content retain their original contract. Pydantic field/model errors reproject decoded resource inputs without bypassing registered error redaction. Known decoded Run error prose is mapped back to its public identifier.

VEX stores `membership:<integer>` internally for its existing authorization checks. Public assignment uses `membership:<UUID>`. Legacy history strings are not FKs: if a referenced membership was removed, the wire value is null with an explicit identity_unavailable flag, rather than leaking an integer or inventing a UUID. Existing persisted history is not rewritten. Direct resource references remain fail-closed on missing conversion.

Revision 102 adds an independent three-table guard, SECURITY INVOKER and fixed pg_catalog search_path. It revokes PUBLIC function execution, retains integer PK/FKs, refuses DBAPI autocommit, requires exactly 101, and uses bounded NOWAIT locks. Unique/NOT NULL/validated UUIDv4 CHECKs and two triggers per table are independently inspected. The original six-resource and User guards, frozen revisions 100/101 and role catalogue are unchanged. The frozen 100 function retains its existing default PUBLIC EXECUTE ACL; the 101 and new 102 functions explicitly revoke PUBLIC EXECUTE. Actual source-derived function owners, SECURITY INVOKER, volatility and search_path were inspected; no legacy ACL was silently tightened or relaxed. No new authorization grant is part of the migration.

Native/OIDC user resolution, JWT subjects, provider issuer/subject pairs, session IDs and Celery keys are unchanged. Actual Chrome checks show platform grant revocation removes effective permission in an existing target session. Global user directory/detail remains 403 for the ordinary platform identity under SBO-73; only existing purpose-limited candidate discovery is exercised positively.

The browser runtime role is NOSUPERUSER/NOCREATEDB/NOCREATEROLE/NOREPLICATION/NOBYPASSRLS. Setup privilege is used only for newly owned databases and fixtures. The full-test launcher targets fixed `_test` names, clean environments, unavailable broker 63392, and collection/per-test routing checks. Its Redis and filesystem artifacts are separate from the original development worker.

Private passwords, setup credentials, JWT/session keys, cookies, raw logs and authenticated traces remain outside the repository. Gitleaks scanned the exact 141 implementation sources and selected reports/evidence with its default rules enabled. Its 11 generic-key findings were reviewed individually: each is an independently verified SHA256 of current or preserved repository source bytes, not a credential or credential digest. There were zero credential findings. The classifications are recorded in evidence/secret-review.json; no detection rule was disabled. Historical private evidence was not republished. The final selected-file scan covered 180 files (6.17 MB) with the same 11 verified source-hash false positives and zero credential findings. An additional in-memory comparison against task secrets found no secret literals; no contents or credential digests were persisted.

The source-dependent populated launcher deliberately refuses revision 102 before any credential/database access. The existing application must not restart on the new source until the separately approved schema cutover. Operator stops/restarts during this task are recorded independently; no task command targets the original API/UI/worker or container lifecycle.

Complete regression and exact source comparison passed. Remaining gates: independent code/security review, populated backup/restore rehearsal and migration authority, CI, staging and live HCL.CS/Entra acceptance. No production/full-UAT sign-off is implied.
